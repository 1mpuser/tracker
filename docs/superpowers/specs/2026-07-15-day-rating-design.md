# Оценка дня (1–10) + комментарий — дизайн

## Мотивация

Числовые метрики (сферы, YouTube, серия) не отражают субъективное ощущение от дня. Нужна короткая, быстрая в заполнении оценка «как прошёл день» по шкале 1–10 плюс место для одной мысли/заметки — привязанные к конкретному дню, видимые как сегодня, так и задним числом, и складывающиеся в тренд за месяц.

## Область действия

- Только один день = одна оценка + один комментарий (не список записей, не история правок).
- Оценка и комментарий необязательны — можно закрыть день, ничего не оценив.
- Редактирование прошлых дней уже покрыто существующим `DayDetailModal` (day-detail-edit фича) — оценка/комментарий встраиваются в него через переиспользование `SpheresPanel`, отдельного UI-пути для прошлых дней не создаётся.

## Backend

### Схема

`Day` получает два новых nullable-поля:

```prisma
model Day {
  ...
  rating         Int?
  comment        String?
  ...
}
```

`rating` — `null` означает «не оценено» (отличается от «оценка 0», которой не существует на шкале 1–10). Требует новой миграции Prisma.

### `PATCH /days/:date` — обобщается на частичное обновление

Сейчас `UpdateDayDto` требует `eveningClosed: boolean` как обязательное поле, а `DaysService.setEveningClosed` жёстко обновляет только этот один флаг. Меняется на:

```ts
class UpdateDayDto {
  eveningClosed?: boolean;
  rating?: number;   // 1..10
  comment?: string;  // max 200 символов
}
```

и `DaysService` получает единый `updateDay(dateStr, dto: {eveningClosed?, rating?, comment?})`, который передаёт `dto` напрямую в `prisma.day.update({ data: dto })` — тот же паттерн частичного апдейта, что уже используется в `CategoriesService.update`. Существующий вызов «закрыть день» на фронте становится частным случаем (`PATCH` с одним только `eveningClosed`), поведение не меняется.

### `GET /days/:date` и `GET /history`

`DayView` получает `rating: number | null`. `HistoryEntry` тоже получает `rating: number | null` — это позволяет 30-дневному графику на фронте переиспользовать уже загруженные 84 дня `history` вместо нового эндпоинта. `comment` в `HistoryEntry` не нужен (график не показывает текст) — только в `DayView`.

## Frontend

### Ввод — `DayRatingBlock` (новый компонент)

Слайдер (`<input type="range" min={1} max={10} step={1}>`), стилизованный под токены приложения (тёмный трек, амбер-заливка/бегунок), текущее значение отображается числом моно-шрифтом рядом со слайдером. Локальное состояние во время перетаскивания (живое визуальное обновление), запрос на сохранение — только по отпусканию (`onMouseUp`/`onTouchEnd`), не на каждое промежуточное значение. Под слайдером — однострочное поле комментария (`maxLength=200`, как у бэкенд-валидации), сохраняется по `onBlur`, тот же паттерн, что у переименования категорий в `SettingsModal`.

Рендерится **внутри** `SpheresPanel`, между списком тумблеров категорий и кнопкой «Отметить день закрытым». `SpheresPanel` получает 4 новых пропса: `rating: number | null`, `comment: string | null`, `onRatingChange: (rating: number) => void`, `onCommentChange: (comment: string) => void` — и просто прокидывает их в `<DayRatingBlock>`, не храня собственного состояния для этого блока.

### Переиспользование в `DayDetailModal`

Поскольку `SpheresPanel` в режиме редактирования прошлого дня уже используется как есть, добавление новых пропсов автоматически даёт возможность редактировать оценку/комментарий и для прошлых дней — колбэки внутри `DayDetailModal` вызывают `updateDay(date, {rating})` / `updateDay(date, {comment})` для выбранной (не обязательно сегодняшней) даты.

В read-only режиме просмотра (до нажатия на карандаш) добавляются две строки текста рядом с существующими «YouTube: N мин» / «День закрыт: да/нет»: «Оценка: N/10» (или «Оценка: —» если не выставлена) и «Комментарий: …» (если есть).

### Статистика — линейный график за 30 дней

Новый компонент `RatingChart` (recharts `LineChart`, как `YoutubeWeeklyChart` использует `BarChart`) в панели «Статистика», после `YoutubeDailyHeatmap`. Данные — последние 30 записей из уже загрученных `history` (`Dashboard` передаёт `history.slice(-30)` или сам компонент фильтрует по длине), точки без оценки (`rating: null`) не рисуются на линии (recharts штатно поддерживает разрывы линии для `null`-значений в `dataKey`).

## Не входит в объём

- Только одна оценка/комментарий на день, без истории изменений.
- Никакой отдельной страницы/списка всех комментариев — только точка на графике + текст в `DayDetailModal`.
- Оценка не участвует в подсчёте серии/хитмепов — это полностью независимая от «выполнено/не выполнено» метрика.
