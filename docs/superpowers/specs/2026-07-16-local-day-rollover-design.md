# Локальное "сегодня" + авто-переключение суток — дизайн

## Мотивация

«Сегодня» на панели сейчас — UTC-календарный день (`todayUTC()`), вычисленный один раз при монтировании `Dashboard` и никогда не пересчитываемый. Итог: в часовом поясе впереди UTC панель может показывать вчерашний день по несколько часов после локальной полуночи, и даже ручной reload не помогает, пока не наступит полночь по UTC. Нужно: (1) «сегодня» = локальный календарный день пользователя, (2) панель сама переключается на новый день при открытой вкладке, без ручного F5.

## Область действия

Побочный эффект пункта 1: `GET /history` на бэкенде якорится на **своё** UTC-«сегодня» (`todayDate()`), независимо от того, что фронт считает «сегодня». Если поменять только фронт, крайняя клетка хитмепов/серии будет несколько часов в сутки не совпадать с датой на панели. Значит `/history` тоже должен принимать явный якорь даты, как остальные `:date`-эндпоинты этого проекта.

## Backend

`DaysService.getHistory(limit: number, endDateStr?: string)` — если `endDateStr` передан, конец диапазона — `parseDateParam(endDateStr)`, иначе (обратная совместимость) `todayDate()`, как сейчас. `GET /history` получает необязательный `?end=` query-параметр, тем же паттерном `@Query` + ручной парсинг, что уже есть у `?limit=`.

## Frontend

- `lib/date.ts`: `todayUTC()` удаляется (после миграции у неё не останется вызывающих кода — по правилам проекта неиспользуемый код не оставляем), добавляется `todayLocal()` — те же `padStart`-вычисления, но через локальные `getFullYear()/getMonth()/getDate()` вместо `getUTC*`. Тот же паттерн, что уже в `notifications.ts` (там это уже осознанное исключение из «везде UTC»).
- `lib/api.ts`: `getHistory(limit: number, end?: string)` — добавляет `&end=${end}` к query-строке, если передан.
- `Dashboard.tsx`: `date` становится обычным `useState` (не разовый инициализатор) с `setDate`. Новый `useEffect` каждые 60 сек плюс на `visibilitychange` сверяет `todayLocal()` с текущим `date` и обновляет при расхождении — существующий `loadCore` уже зависит от `[date]`, так что смена даты сама вызывает перезагрузку дня/истории/настроек. Оба вызова `getHistory` (`loadCore`, `refreshHistory`) передают `date` вторым аргументом.
- `StreakHeatmap.tsx`, `CategoryHeatmap.tsx`: `todayUTC()` → `todayLocal()` для подсветки «сегодняшней» клетки — теперь совпадает и с панелью, и с якорем `/history`.

## Не входит в объём

- Никакого визуального уведомления о том, что день переключился — просто тихий перезапрос данных (как при обычной загрузке).
- `parseUTC`/`formatUTC`/`addDaysUTC` не меняются — это чистые преобразования уже известной строки даты, к «что сейчас» отношения не имеют.
