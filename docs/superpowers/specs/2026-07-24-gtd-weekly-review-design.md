# GTD Этап C.1 — воскресное напоминание Weekly Review — дизайн

## Мотивация

GTD держится на двух ритмах: ежедневный разбор Корзины (уже есть привычка) и **еженедельный Weekly Review** — пройтись по Корзине, Бэклогу, Проектам, Ожиданию, поднять что-то из «Когда-нибудь». Пользователь явно попросил напоминание, которое «выскакивает в воскресенье». Это первая из трёх фич Этапа C (дальше — приоритет/дедлайн, экспорт Заметок в Obsidian; отдельными спеками).

## Решения (зафиксировано на брейншторме)

- **Никакого отдельного крона/бэкенда.** Переиспользуем существующий фронт-цикл уведомлений в `Dashboard` (`check()` каждые 10 мин при `settings.notificationsEnabled` + granted permission), как утреннее/вечернее/помидорное напоминания. Крон в спящем контейнере неуместен — уведомление всё равно живёт в браузере.
- **Триггер:** воскресенье, локальное время `hour >= 11` (по образцу локальных окон `isMorningWindow`/`isEveningWindow` — намеренно wall-clock, не UTC).
- **Один раз за воскресенье.** В отличие от вечернего напоминания (долбит каждые 10 мин в окне), Weekly Review показывается **один раз в день**: защита через `localStorage` — ключ `weeklyReviewNotified` хранит дату (`todayLocal()`) последнего показа; уведомление шлётся, только если сегодняшняя дата ещё не помечена.
- **Баннер на GTD-экране** по воскресеньям — тонкая строка сверху «🗓 Воскресный разбор — время для Weekly Review». Без логики закрытия, просто рендерится по воскресеньям (`new Date().getDay() === 0`). Виден даже без включённых уведомлений.
- Текст уведомления: «Воскресенье — время для Weekly Review: разбери Корзину, пройдись по Бэклогу и Проектам».

## Frontend

### `lib/notifications.ts`
- Новая чистая функция `isWeeklyReviewWindow(now: Date): boolean` — `now.getDay() === 0 && now.getHours() >= 11` (локальное время). Покрывается спекой (`notifications.spec.ts`): воскресенье до 11 → false, воскресенье в 11+ → true, другой день → false.

### `Dashboard.tsx` — уведомление
В существующий `check()` (внутри notification-`useEffect`) добавить ветку:
```ts
if (isWeeklyReviewWindow(now)) {
  const key = todayLocal();
  if (localStorage.getItem('weeklyReviewNotified') !== key) {
    new Notification('Воскресенье — время для Weekly Review: разбери Корзину, пройдись по Бэклогу и Проектам');
    localStorage.setItem('weeklyReviewNotified', key);
  }
}
```
`isWeeklyReviewWindow` импортируется из `@/lib/notifications`; `todayLocal` уже импортирован.

### `GtdScreen.tsx` — баннер
Сверху экрана (перед корзинной навигацией) при `new Date().getDay() === 0` рендерить строку-баннер:
```tsx
{new Date().getDay() === 0 && (
  <div className={styles.reviewBanner}>🗓 Воскресный разбор — время для Weekly Review</div>
)}
```
Класс `.reviewBanner` — из дизайн-токенов (`--accent-soft`/`--accent`/`--radius`).

## Тесты (TDD)
- **Frontend** (`lib/notifications.spec.ts`): `isWeeklyReviewWindow` — воскресенье 10:59 → false, воскресенье 11:00 → true, воскресенье 18:00 → true, будний день 12:00 → false. Даты конструируются как локальные (`new Date(2026, month, day, hour, min)`), т.к. функция читает `getDay`/`getHours` (локальные).
- Компоненты (`Dashboard`/`GtdScreen`) — гейт `bun run build`; логика окна покрыта в `lib/`.

## Не входит в объём
- Приоритет/дедлайн/оценка (C.2), экспорт Заметок в Obsidian (C.3) — отдельные спеки.
- Никакого чек-листа/мастера Weekly Review внутри приложения — только напоминание + баннер. Сам разбор пользователь делает по существующим корзинам GTD.
- Настройка времени/дня напоминания в UI — зашито (воскресенье, 11:00), меняется правкой кода.
- Бэкенд/крон/серверные пуши — не трогаются.
