# Просмотр и редактирование прошлых дней — дизайн

## Мотивация

Трекер до этой фичи позволял видеть и редактировать только сегодняшний день. Хитмеп сфер (12 недель) уже показывает исторические данные, но только как read-only tooltip при наведении. На практике данные за прошлый день иногда не соответствуют факту: пользователь мог заснуть до того, как отметил сферы, пропустить напоминания, но по факту дела сделать — трекер в итоге показывает «0 из 5» за день, когда реально было иначе. Нужен способ зайти в конкретный прошлый день и поправить данные под факт: сферы, YouTube-минуты, флаг «день закрыт», дейлики.

## Область действия

Только фронтенд. Бэкенд не меняется — каждый нужный эндпоинт (`PATCH /days/:date/categories/:key`, `PATCH /days/:date`, `PATCH /days/:date/youtube`, `POST/PATCH/DELETE /days/:date/dailies`, `GET /days/:date`) уже принимает произвольную дату; это было заложено в Plan 1 и никогда не использовалось фронтендом ни для чего, кроме сегодняшней даты.

Не входит в объём:
- Бюджет YouTube (`Settings.youtubeBudget`) не редактируется из карточки дня — это глобальная настройка, не привязанная к дате, редактируется только в общей панели YouTube на главном экране.
- Редактирование сегодняшнего дня через новую модалку не предусмотрено — сегодня уже полностью редактируется на главном экране, дублировать эту возможность не нужно.
- YouTube-хитмеп (30 дней, `YoutubeDailyHeatmap`) остаётся некликабельным — только tooltip при наведении, как сейчас.

## Триггер

Клик по клетке 12-недельного хитмепа сфер (`CategoryHeatmap`, компонент из Plan 2 Task 12) открывает модалку карточки дня для даты этой клетки.

- Клик по клетке **сегодняшнего дня** — no-op (ничего не происходит).
- Клик по клетке **без данных** (blank-паддинг клетка перед первым днём истории) — no-op, у неё нет даты.
- Клик по любой другой клетке (включая дни без единого отмеченного действия, где `completed: 0`) — открывает модалку.

## Компонент: `DayDetailModal`

Новый компонент `frontend/components/DayDetailModal.tsx` + `.module.css`, по структуре модалки повторяет `SettingsModal` (Plan 2 Task 16): тёмный оверлей, центрированная панель, закрытие по клику вне панели / крестику / Escape.

### Состояния модалки

1. **Загрузка** — модалка открылась, идёт `getDay(date)`. Показывает лёгкий лоадер-текст.
2. **Просмотр (read-only)** — дефолтное состояние после загрузки. Показывает:
   - Дату в шапке (тем же форматом, что и главный экран — `formatDisplayDate`).
   - Список категорий: label + иконка ✓ (done) или пусто (not done), без интерактивных тумблеров.
   - Текст «YouTube: N мин».
   - Текст «День закрыт: да/нет».
   - Список дейликов: текст, зачёркнутый если `done`, без чекбоксов/кнопок удаления.
   - Иконка карандаша в шапке (рядом с крестиком закрытия).
3. **Подтверждение редактирования** — клик по карандашу заменяет read-only блок на инлайн-подтверждение (внутри той же модалки, не отдельным окном):
   > «Редактировать данные за {дата}? Это повлияет на серию и статистику.»
   Две кнопки: «Отмена» (возврат к состоянию 2) и «Редактировать» (переход к состоянию 4).
4. **Редактирование** — переиспользует существующие компоненты без изменения их интерфейсов:
   - `SpheresPanel` (Plan 2 Task 9) — те же пропсы (`categories`, `eveningClosed`, `onToggle`, `onToggleEveningClosed`), только колбэки внутри `DayDetailModal` вызывают `setCategoryDone(selectedDate, key, done)` / `setEveningClosed(selectedDate, closed)` вместо сегодняшней даты.
   - `DailiesPanel` (Plan 2 Task 10) — те же пропсы (`dailies`, `onAdd`, `onToggle`, `onDelete`), колбэки вызывают `addDaily(selectedDate, text)` / `updateDaily(id, {...})` / `deleteDaily(id)`. Кнопка «из шаблонов» работает как обычно (шаблоны не привязаны к дате).
   - Новый маленький инлайн-блок YouTube внутри `DayDetailModal` (не отдельный файл — слишком мал и используется только здесь): число минут + кнопки `+10/+25/+50` + «сбросить», без поля бюджета. Вызывает `updateYoutube(selectedDate, {delta})` / `updateYoutube(selectedDate, {reset: true})`.
   - После каждой мутации модалка перезапрашивает `getDay(selectedDate)` (обновить свой локальный вид) и дёргает переданный проп `onDataChanged()` — это обновляет `history` на уровне `Dashboard`, так что клетка хитмепа перекрашивается вживую без закрытия модалки.

### Пропсы

```ts
interface DayDetailModalProps {
  date: string;             // YYYY-MM-DD, UTC — дата выбранной клетки
  onClose: () => void;
  onDataChanged: () => void; // Dashboard передаёт сюда refreshHistory
}
```

## Изменения в существующих файлах

- `frontend/components/CategoryHeatmap.tsx`: клетки становятся кликабельными (кроме сегодняшней и блан-паддинга). Новый проп `onSelectDate: (date: string) => void`.
- `frontend/components/Dashboard.tsx`: новое состояние `selectedDate: string | null`, рендер `<DayDetailModal>` при непустом значении, `onClose` сбрасывает `selectedDate` в `null`, `onDataChanged` = существующий `refreshHistory`.

## Данные и типы

Никаких новых типов в `types/api.ts` не требуется — `DayView`, `CategoryView`, `DailyTaskView` уже описывают всё, что нужно карточке дня (это тот же тип, что возвращает `getDay()` для сегодня).

## Тестирование

Вся логика в этой фиче — либо переиспользование уже протестированных `lib/api.ts` функций (Plan 2 Task 2), либо чисто UI-стейт машина внутри `DayDetailModal` (загрузка → просмотр → подтверждение → редактирование), которая по духу проекта проверяется вручную в браузере, а не юнит-тестами (аналогично `SettingsModal` в Plan 2 Task 16 — там тоже не было отдельных юнит-тестов на open/close/tab-switch стейт-машину).
