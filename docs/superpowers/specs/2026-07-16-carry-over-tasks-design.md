# Перенос невыполненных задач с прошлых дней — дизайн

## Мотивация

Задачи дня (`DailyTask`) живут только внутри своего дня — если что-то не сделано, оно просто остаётся невыполненным в истории, и назавтра приходится вручную вспоминать и перепечатывать текст. Нужен способ по требованию подтянуть в текущий день ещё не закрытые задачи за недавнее прошлое, не трогая исторические данные тех дней.

## Область действия

- Перенос запускается только вручную, кнопкой — никакой автоматики при открытии дня.
- Кандидаты ищутся в окне **последних 3 дней** перед просматриваемой датой.
- Перенос — это **создание копии** в текущем дне; исходная задача в своём дне остаётся как была (`done: false`), чтобы не искажать историческую статистику того дня.
- Одна и та же задача не должна предлагаться повторно после того, как её уже перенесли — предлагается только самая свежая копия в цепочке.
- Кнопка доступна везде, где рендерится `DailiesPanel` — то есть и на главном экране (сегодня), и в `DayDetailModal` в режиме редактирования прошлого дня (перенос там тоже возможен, из ещё более ранних дней). Это следствие существующего принципа «`DailiesPanel` используется с одинаковыми пропсами без веток», отдельного UI-пути не создаётся.
- Без дедупликации по тексту: если сегодня уже есть задача с таким же текстом (введённая вручную или из шаблона), перенос всё равно создаст вторую строку — не усложняем сравнением текста.

## Backend

### Схема

`DailyTask` получает два новых nullable/default поля:

```prisma
model DailyTask {
  id               Int       @id @default(autoincrement())
  day              Day       @relation(fields: [dayId], references: [id], onDelete: Cascade)
  dayId            Int
  text             String
  done             Boolean   @default(false)
  order            Int       @default(0)
  carriedFromDate  DateTime? @db.Date
  carriedForward   Boolean   @default(false)
  createdAt        DateTime  @default(now())
}
```

- `carriedFromDate` — дата **первого** появления этой формулировки задачи (не дата предыдущего переноса). Проставляется при создании копии; если у исходной задачи уже было своё `carriedFromDate`, оно копируется как есть, иначе берётся дата дня исходной задачи. Так бейдж всегда показывает «висит с …», а не «перенесено вчера» на пятый день подряд.
- `carriedForward` — `true` ставится на **исходной** задаче в момент, когда с неё сделали копию. Используется только для исключения из будущей выборки кандидатов, на отображение и статистику не влияет.
- Требует новой миграции Prisma.

### `GET /days/:date/carry-candidates?days=3`

Возвращает незакрытые задачи за `days` дней до `:date` (сам `:date` не включается), у которых `carriedForward = false`:

```ts
interface CarryCandidate {
  id: number;
  text: string;
  originDate: string; // day.date самой задачи (или carriedFromDate, если уже была перенесена раньше)
}
```

Реализация в `DailiesService` (или новом методе там же): вычислить диапазон дат через `addDays(parseDateParam(date), -days)` .. `addDays(parseDateParam(date), -1)` (переиспользуя `common/date.util.ts`), затем:

```ts
this.prisma.dailyTask.findMany({
  where: {
    done: false,
    carriedForward: false,
    day: { date: { gte: rangeStart, lte: rangeEnd } },
  },
  include: { day: true },
  orderBy: { day: { date: 'desc' } },
});
```

`days` — query-параметр с дефолтом `3` (валидируется `@IsOptional() @IsInt() @Min(1)` через DTO, как остальные query-параметры в проекте).

### `POST /days/:date/dailies/carry`

Тело: `{ ids: number[] }`. Для каждого `id`:

1. Найти `DailyTask` по `id`. Если не найден, либо `done: true`, либо `carriedForward: true` — пропустить (без ошибки на весь батч, это личный однопользовательский инструмент, гоняться за гонками кликов незачем).
2. Создать новую `DailyTask` в дне `:date` (через существующий `daysService.getOrCreateDayId(date)`, как в `DailiesService.create`): `text` скопирован, `done: false`, `order` — следующий по счёту (как в `create`), `carriedFromDate = existing.carriedFromDate ?? existing.day.date`.
3. Обновить исходную задачу: `carriedForward: true`.

Оба шага на один `id` — в одной `prisma.$transaction`, чтобы не оставить исходную задачу непомеченной при обрыве запроса на середине батча.

Возвращает обновлённый `DayView` для `:date` (тот же формат, что отдают `GET /days/:date` и остальные мутации) — фронту не придётся делать отдельный `refreshDay()`.

## Frontend

### `types/api.ts`

```ts
interface DailyTaskView {
  id: number;
  text: string;
  done: boolean;
  order: number;
  carriedFromDate: string | null;
}

interface CarryCandidate {
  id: number;
  text: string;
  originDate: string;
}
```

### `lib/api.ts`

```ts
export function getCarryCandidates(date: string, days = 3): Promise<CarryCandidate[]> {
  return request(`/days/${date}/carry-candidates?days=${days}`);
}

export function carryDailies(date: string, ids: number[]): Promise<DayView> {
  return request(`/days/${date}/dailies/carry`, {
    method: 'POST',
    body: JSON.stringify({ ids }),
  });
}
```

### `DailiesPanel`

Новая кнопка «перенести с прошлых дней» рядом с «из шаблонов», тот же визуальный паттерн (кнопка + выпадающий блок). По клику — `getCarryCandidates(date)`; если список пуст, кнопка не открывает пустой дропдаун (можно сразу задизейблить кнопку, если кандидатов нет — как и «из шаблонов» уже показывает «Шаблонов пока нет» при пустом списке, здесь для консистентности лучше просто не открывать дропдаун и не дёргать лишний рендер, а показать короткую надпись, если список пуст).

Дропдаун — список чекбоксов (не клик-по-строке-сразу-добавляет, как у шаблонов, а множественный выбор):

```
[ ] Залить на стенд апку          с 14 июля
[ ] Разобрать почту                 вчера
                 [ Перенести выбранное (2) ]
```

Кнопка «Перенести выбранное» задизейблена, пока не выбрано ни одного чекбокса.

`DailiesPanel` получает `date: string` пропом (нужен, чтобы самостоятельно вызывать `getCarryCandidates(date)` — по тому же самоконтролируемому паттерну, что уже есть у `getTaskTemplates()`) и новый колбэк `onCarry: (ids: number[]) => void`. Чтение кандидатов панель делает сама, а сама мутация переноса — как `onAdd`/`onToggle`/`onDelete` — остаётся за родителем: по клику на «Перенести выбранное» панель вызывает `onCarry(selectedIds)`, закрывает дропдаун и сбрасывает локальный выбор.

`Dashboard` и `DayDetailModal` реализуют `onCarry` одинаково — `carryDailies` уже возвращает полный `DayView`, поэтому это просто `setDay(await carryDailies(date, ids))`, без отдельного рефетча (тот же приём, что у `changeRating`/`toggleCategory`). `refreshHistory()` не нужен: перенесённая копия создаётся с `done: false` и не меняет счётчики категорий, на которых считается история/хитмепы.

Компактный формат даты происхождения — маленький хелпер в `lib/date.ts`: разница в 1 день от сегодня → «вчера», в 2 дня → «позавчера», иначе → «с {formatDisplayDate(originDate)}» (переиспользует уже существующий `formatDisplayDate`).

### Бейдж перенесённой задачи

В списке задач дня (там же, где рендерится `d.text`) — если `d.carriedFromDate !== null`, рядом с текстом маленькая серая пометка `↻ с 14 июля` (тем же хелпером форматирования дат, что и в кандидатах). Стилизуется как второстепенный текст (как дата в `dropdownItem` у кандидатов) — не конкурирует по вниманию с самим текстом задачи или чекбоксом выполнения.

## Не входит в объём

- Никакой автоматики: перенос только по явному клику, никогда сам по себе при открытии дня.
- Никакого лимита на количество раз, сколько задача может быть перенесена подряд — цепочка «не сделал → перенёс → не сделал → перенёс» ничем не ограничена, кроме `days`-окна поиска кандидатов (если задачу не переносить 3+ дня, она перестаёт предлагаться, но не удаляется — просто выпадает из окна, найти её можно вручную открыв старый день).
- Никакой дедупликации по тексту между перенесённой задачей и уже существующей в целевом дне.
- Перенос не переносит `order` относительно других задач — новая копия просто добавляется в конец списка дня, как обычная новая задача.
