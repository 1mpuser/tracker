# Учётки выдаёт админ, без Resend — дизайн

Статус: **утверждено владельцем 2026-09-12**. Заменяет «Развилку 3. Вход» из `2026-09-11-multi-user-hosting-design.md` в части регистрации, писем и сброса пароля; вход по паролю, сессии и изоляция данных остаются как там.

## Что хотим

1. **Никаких писем и никакого Resend** — ни регистрации по почте, ни сброса пароля по почте. С внешним почтовым сервисом не взаимодействуем.
2. **Самостоятельной регистрации нет.** Учётки создаёт мастер-учётка (админ) в отдельном разделе `/admin`: почта (как логин) + пароль. Админ сам раздаёт доступы людям.
3. Админ может: создать учётку, сменить её пароль, заблокировать/разблокировать, удалить со всеми данными.
4. Telegram-боты, iCloud, Session и всё остальное пер-пользовательское — без изменений.

## Решения владельца

- **Кто админ:** флаг у пользователя в БД. Владелец становится админом при переезде (`set-owner`); отдельный скрипт `make-admin` — на всякий случай. Через env не настраивается.
- **Пароль новой учётки:** генерируется в форме, можно поправить руками; после создания показывается один раз с кнопкой «Скопировать».
- **Раздел админа:** отдельная страница `/admin`, ссылка в шапке видна только админу.

## Что удаляется

Бэкенд:
- эндпоинты `POST /auth/register`, `/auth/register/confirm`, `/auth/register/resend`, `/auth/forgot`, `/auth/reset` и их DTO (`register`, `confirm*`, `resend`, `forgot`, `reset`);
- `MailerService`, `mail-templates.ts`, всё про Resend;
- в `auth.config.ts` — `signupMode`, allowlist, `RESEND_API_KEY`, `MAIL_FROM`, лимит писем (`MAIL_PER_HOUR`) и `APP_URL` (он использовался только для ссылок в письмах); остаётся то, что нужно входу и cookie (срок сессии, `cookieSecure`);
- модели `PendingSignup` и `PasswordReset` (и связь `User.passwordResets`) — новой миграцией `DROP TABLE`. В проде этих таблиц ещё нет, данных в них терять нечего;
- код чистки просроченных `PendingSignup`/`PasswordReset` (чистка просроченных `Session` остаётся).

Фронтенд: страницы `/register`, `/register/confirm`, `/forgot`, `/reset`, их функции в `lib/api.ts`, ссылки «Регистрация»/«Забыли пароль» со страницы входа.

Деплой и доки: `RESEND_API_KEY`/`MAIL_FROM`/`APP_URL` из `docker-compose.prod.yml`, `.env.prod.example`, `.env.example`, `deploy/deploy.sh`, `deploy/transit/*`; разделы про Resend/DNS-записи почты (DKIM/SPF/MX) в `docs/deploy.md` и README. Бэкенд в проде больше не требует этих переменных.

## Данные

`User` получает два поля:
- `isAdmin Boolean @default(false)`;
- `blockedAt DateTime?` — `null` = активна.

`AuthUser` (`auth/auth-user.ts`) расширяется полем `isAdmin` — фронтенд узнаёт о правах из `GET /auth/me`.

Скрипты (`backend/scripts/`):
- `set-owner` — дополнительно ставит `isAdmin = true`;
- `make-admin --email <адрес>` — ставит флаг существующему пользователю; ошибка, если такого нет.
- `reset-password` остаётся (аварийный путь, если админ сам забыл пароль).

## Бэкенд: модуль `admin/`

`admin.controller.ts`, `admin.service.ts`, `admin.module.ts`, `dto/`, `admin.service.spec.ts` — по образцу остальных модулей (сервис тестируется с мок-Prisma, `new AdminService(...)`).

Доступ: декоратор/guard `AdminGuard` на весь контроллер поверх глобального `SessionGuard`. Не-админ получает **404** (как чужая запись в остальном API — наличие админки не раскрывается).

| Метод | Путь | Тело | Ответ |
|---|---|---|---|
| GET | `/admin/users` | — | `[{ id, email, timezone, isAdmin, blockedAt, createdAt }]`, по `createdAt` |
| POST | `/admin/users` | `{ email, password, timezone? }` | созданная учётка (как в списке), 201 |
| POST | `/admin/users/:id/password` | `{ password }` | 204 |
| POST | `/admin/users/:id/block` | — | 204 |
| POST | `/admin/users/:id/unblock` | — | 204 |
| DELETE | `/admin/users/:id` | — | 204 |

Правила:
- почта нормализуется (trim + lowercase), `@IsEmail`; занятый адрес → 409;
- пароль 8–128 символов (как в смене пароля);
- `timezone` проверяется так же, как в `updateTimezone` (через `Intl.DateTimeFormat`), по умолчанию `Europe/Moscow`; неизвестный → 400;
- создание — через `UserBootstrapService.createUser`, который переводится **в одну транзакцию** (пользователь + настройки + сферы; сейчас это три отдельных запроса);
- смена пароля и блокировка **удаляют все сессии** учётки;
- админ не может заблокировать или удалить **себя** → 400 (не остаться без админа);
- несуществующий `:id` → 404;
- удаление — `prisma.user.delete`, все пользовательские таблицы уже `onDelete: Cascade`.

Блокировка на входе и в каждом запросе:
- `login` для заблокированной учётки отвечает так же, как на неверный пароль (401, без раскрытия причины);
- `resolveSession` возвращает `null`, если `blockedAt` не пуст — живая сессия заблокированного перестаёт работать сразу.

## Фронтенд

- Страница `app/admin/page.tsx` (client, стиль как у остальных — CSS Module + токены из `globals.css`, без UI-библиотек).
  - При загрузке `getMe()`; не админ → `router.replace('/')`.
  - Таблица учёток: почта, пояс, создана, статус (активна / заблокирована), метка «админ».
  - Форма «Новая учётка»: почта, пароль (сразу сгенерирован, можно править, кнопка «Сгенерировать заново»), пояс (по умолчанию `Europe/Moscow`). После создания — блок с почтой и паролем и кнопкой «Скопировать» (один раз, до закрытия).
  - Действия в строке: «Сменить пароль» (та же генерация + показ один раз), «Заблокировать»/«Разблокировать», «Удалить» — с подтверждением вводом почты учётки. Для своей строки блокировка и удаление недоступны.
  - Ошибки — через `apiErrorMessage`.
- Генерация пароля — чистая функция в `lib/password.ts` (`crypto.getRandomValues`, 16 символов, без похожих символов вроде `0/O`, `1/l`), покрыта тестом.
- `lib/api.ts`: функции для всех `/admin/*`; тип `AuthUser` получает `isAdmin`.
- `Header`: ссылка «Админка» рядом с шестерёнкой, только если `me.isAdmin`.

## Попутно: исправления из ревью ветки

Ревью `master...feat/multi-user` (2026-09-12). Пункты 2, 4, 8 (лимит писем, пояс при регистрации, гонка подтверждения) исчезают вместе с регистрацией. Остальное чиним здесь:

1. **Лимиты запросов не работают.** `ThrottlerModule` подключён, но `ThrottlerGuard` не зарегистрирован → `@Throttle` ничего не делает, `/auth/login` открыт для перебора. Зарегистрировать `ThrottlerGuard` как `APP_GUARD`; лимит на `login` оставить (5/мин).
2. **Сессия не продлевается.** `resolveSession` обновляет только `lastSeenAt`. Раз в сутки при активности продлевать `expiresAt` на `sessionDays` и переустанавливать cookie `sid` с новым `maxAge`.
3. **`routines.update` не проверяет владельца `categoryId`** (`create` проверяет) → можно привязать чужую категорию. Проверять так же, как в `create`; чужая → 404.
4. **`POST /integrations/icloud/resync`** передаёт в синхронизацию сырые строки Prisma (`Date` вместо строки даты) → падает внутри и глотается, пользователь видит «Обновлено: N». Плюс в выборку попадают `done`-задачи. Привести данные к формату, который ждёт синк, исключить завершённые; сообщать реальное число синхронизированных.
5. **Ошибка расшифровки секрета роняет запросы** (`integrations.service.ts`, `telegram-config.service.ts`, `icloud.service.ts`): при сменённом `APP_ENCRYPTION_KEY` `GET /settings` отвечает 500, дашборд не грузится. Ловить ошибку, логировать без секрета, считать интеграцию «не настроена / нужно ввести заново», не ломая основной ответ.
6. **Кэш календарей CalDAV** (`caldav.client.ts`) по ключу `userId:name` без отпечатка учётки → после смены Apple ID подхватывается старый список. Включить в ключ отпечаток учётки (например, хэш Apple ID) или сбрасывать кэш пользователя при `setICloud`.
7. **Дубль вкладки «Чаты»** в `SettingsModal.tsx`.
8. **`deploy/transit/4-disarm-local.sh`**: BSD sed не понимает `\0` → строки `.env` ломаются в `;0…`, а `;` не комментарий. Заменить на `#&`. (Если после удаления Resend в скрипте останутся только Telegram/iCloud/Session-переменные — поправить список.)
9. **`truncateAll` в e2e** чистит любую БД, к которой подключён. Добавить защиту: если имя базы в `DATABASE_URL` не содержит `test` — бросать ошибку до `TRUNCATE`.

## Тесты

Юнит:
- `AdminService`: создание (нормализация почты, 409 на занятый, 400 на плохой пояс, транзакция), смена пароля и блокировка удаляют сессии, запрет на себя, 404 на несуществующий id;
- `AuthService`: заблокированный не входит; `resolveSession` для заблокированного → `null`; продление сессии;
- `routines.update` с чужой категорией → 404;
- `lib/password.ts` на фронтенде.

E2e (реальная БД, `tracker_test`):
- обычный пользователь получает 404 на все `/admin/*`;
- админ создаёт учётку → новый пользователь входит с выданным паролем и видит пустой, но валидный аккаунт;
- блокировка → живая сессия заблокированного сразу получает 401; разблокировка → снова входит;
- смена пароля админом → старая сессия 401, новый пароль работает;
- удаление → данные удалённого исчезли, данные админа и третьего пользователя на месте;
- `/auth/register`, `/auth/forgot`, `/auth/reset` → 404.

Приёмка: `bun run test`, `bun run test:e2e`, `bun run build` в `backend/`; `bun run test`, `bun run build` во `frontend/`; `bunx prisma migrate diff` пуст; `docker compose -f docker-compose.prod.yml config` без `RESEND_*`/`MAIL_FROM` проходит с заполненным `.env.prod`; `grep -rniE "resend|mailer|PendingSignup|PasswordReset" backend/src frontend/app frontend/components frontend/lib` пуст.

## Вне скоупа

- Несколько админов через интерфейс (назначение — только скриптом `make-admin`).
- Журнал действий админа.
- Принудительная смена пароля при первом входе (пользователь может сменить сам во вкладке «Аккаунт»).
- Логины не в виде почты.
