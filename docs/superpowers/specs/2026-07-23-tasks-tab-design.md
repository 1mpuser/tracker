# Вкладка «Задачи» — обзор всех задач по всем дням — дизайн

## Мотивация

Сейчас задачи (`DailyTask`) привязаны к дню и видны **только за сегодня** (панель «Задачи на сегодня») либо за один прошлый день (через `DayDetailModal`). Единого места, где видно **все** задачи сразу, нет.

Нужен отдельный экран-обзор всех задач по всем дням: посмотреть, что вообще было, отфильтровать выполненные/невыполненные, найти по тексту. Экран открывается через **таб-бар** — первый шаг к многоэкранному приложению.

Это **первый этап**. Полноценный GTD (дедлайны, приоритеты, оценки, inbox, контексты, проекты) — **отдельный следующий этап** поверх новой сущности; здесь его нет. Этот экран задаёт каркас навигации, на который GTD потом ляжет.

## Решения (зафиксировано на брейншторме)

- **Обзор всех `DailyTask` по всем дням** (вариант A), а не перенос сегодняшнего списка в таб.
- **Таб-бар на верхнем уровне** — там, где сейчас строка `sys / daily-tracker`. Сама надпись `sys / daily-tracker` смысловой нагрузки не несёт: демотится в мелкую приглушённую подпись в углу этой же строки (позже может быть убрана совсем). Главный элемент уровня — переключатель табов.
- **Без роутинга.** Переключение табов — через локальный стейт в `Dashboard` (`activeTab`), в русле текущего паттерна «всё client-fetched, ничего не SSR-ится». URL не меняется.
- **Таб-бар расширяемый** — массив `{ key, label }`. Сейчас два таба: «Главный» и «Задачи». GTD и прочее добавляются одной записью.
- **`TasksScreen` — self-contained**, сам фетчит данные на маунте (как `CategoryBars` / `YoutubeDailyHeatmap` / `TaskTemplatesTab`), не тянет всё через пропсы `Dashboard`.
- **Список read-only.** Правки задач — кликом по дню, который открывает **существующую** `DayDetailModal`. Никакой новой логики мутаций/тоглов на этом экране (инлайн-тоггл и удаление сознательно отложены).
- **Фильтрация и поиск — клиентские.** Single-user, объёмы небольшие; сервер отдаёт всё, фронт группирует/фильтрует.

## Модель данных

Изменений нет. Экран читает существующую модель `DailyTask` (`id`, `text`, `done`, `order`, `carriedFromDate`, `carriedForward`, связь с `Day.date`). Миграций нет.

## Backend

Один новый эндпоинт «все задачи», в существующем `dailies`-модуле (сервис + контроллер + спека).

- **`DailiesService.getAllTasks(): Promise<TaskOverviewItem[]>`**
  - Читает все `DailyTask` с `include: { day: true }`, `orderBy: [{ day: { date: 'desc' } }, { order: 'asc' }]`.
  - Мапит в плоский вид: `{ id, text, done, date, carriedFromDate, carriedForward }`, где `date = formatDate(t.day.date)` и `carriedFromDate = t.carriedFromDate ? formatDate(t.carriedFromDate) : null` (строки `YYYY-MM-DD`, как во всём API — даты сериализуются через `formatDate`, не отдаются как `Date`).
- **`DailiesController`**: `@Get('tasks')` → `getAllTasks()`. Роут-префикс `tasks` в русле контроллера со смешанными путями (`days/:date/...`, `dailies/:id`).
- Серверные фильтры/пагинация не делаются (YAGNI для single-user). Если данные разрастутся — добавим `?status=` / пагинацию позже.

Тип возврата (интерфейс `TaskOverviewItem`) объявляется рядом с сервисом, как `CarryCandidate` в `dailies.service.ts`.

## Frontend — навигация (`Dashboard` как шелл)

`Dashboard` остаётся владельцем данных «Главного» экрана и одновременно становится шеллом с табами.

- Новый стейт `const [activeTab, setActiveTab] = useState<'home' | 'tasks'>('home')`.
- Верхняя строка (сейчас `<div className={styles.sysline}>sys / daily-tracker</div>`) заменяется на **строку таб-бара**: слева переключатель табов, справа мелкая приглушённая подпись `sys / daily-tracker`. Шестерёнка настроек пока остаётся в `Header` (доступна на «Главном»); на этом этапе не переносится.
- Таб **«Главный»** (`activeTab === 'home'`): текущий контент as-is — `Header` + грид панелей (`SpheresPanel`/`DailiesPanel`/`YoutubePanel`/`PomodoroPanel`) + `StatsPanel`. Просто заворачивается в условие, внутренняя логика/хендлеры не меняются.
- Таб **«Задачи»** (`activeTab === 'tasks'`): рендерится `<TasksScreen onSelectDate={setSelectedDate} refreshKey={tasksRefreshKey} />`.
- **`DayDetailModal` остаётся на уровне `Dashboard`** (как сейчас, триггерится `selectedDate`) — работает для обоих табов без дублирования. `TasksScreen` открывает её тем же `setSelectedDate`.
- **Рефреш после правок из модалки на табе «Задачи»:** `DayDetailModal`-проп `onDataChanged` уже рефрешит историю; на табе «Задачи» также нужно перезагрузить список задач. Вводится `const [tasksRefreshKey, setTasksRefreshKey] = useState(0)`; `onDataChanged` дополнительно делает `setTasksRefreshKey((k) => k + 1)`. `TasksScreen` перечитывает данные при изменении `refreshKey` (в зависимостях `useEffect`).

Таб-бар и мелкая sysline-подпись — новая разметка + стили в `Dashboard.module.css` (классы `tabBar`, `tab`, `tabActive`, `sysHint`), из существующих дизайн-токенов. Отдельный компонент под таб-бар не выделяется — двух табов мало; при росте вынесем.

## Frontend — экран `TasksScreen`

Новый self-contained `'use client'` компонент (`components/TasksScreen.tsx` + `.module.css`).

- **Стейт:** `items: TaskOverviewItem[]`, `loading`, `filter: 'all' | 'pending' | 'done'`, `query: string`.
- **Фетч:** `useEffect(() => { getAllTasks().then(setItems) }, [refreshKey])` (перезагрузка при бампе `refreshKey`).
- **Пропсы:** `onSelectDate(date: string): void`, `refreshKey: number`.
- **Верхняя панель управления:**
  - Заголовок «Все задачи».
  - Сегмент-фильтр «Все / Невыполненные / Выполненные» (`filter`).
  - Поле поиска по тексту (`query`, case-insensitive `includes`).
- **Список:** отфильтрованные задачи **группируются по `date`** (свежие дни сверху). Для каждого дня — заголовок с датой (`formatDisplayDate`) и счётчиком `выполнено/всего` за день (по невыфильтрованным задачам дня, чтобы «2/4» не врало при активном фильтре — считается по всем задачам дня, отображается всегда). Под заголовком — строки задач:
  - статус-глиф `✓` (done) / `☐` (pending),
  - текст (у done — приглушённый/зачёркнутый, как в `DailiesPanel`),
  - бейдж переноса `↻ с <дата>` при `carriedFromDate` (форматирование как `formatOriginDate` в `DailiesPanel`).
- **Клик по заголовку дня** → `onSelectDate(date)` → `Dashboard` открывает `DayDetailModal` для этого дня. Строки задач сами по себе кликом ничего не мутируют (read-only).
- **Пустые состояния:** «Задач пока нет» (совсем пусто) / «Ничего не найдено» (пусто после фильтра/поиска).

Логика группировки достаточно простая, чтобы жить внутри компонента; если понадобится тестируемая чистая функция группировки — выносится в `lib/` отдельным шагом (сейчас не требуется).

## API-клиент и типы (`frontend/`)

- **`lib/api.ts`**: `getAllTasks(): Promise<TaskOverviewItem[]>` → `GET /tasks`.
- **`types/api.ts`**: новый интерфейс
  ```ts
  export interface TaskOverviewItem {
    id: number;
    text: string;
    done: boolean;
    date: string;              // YYYY-MM-DD — день задачи
    carriedFromDate: string | null;
    carriedForward: boolean;
  }
  ```

## Тесты (TDD)

- **Backend** (`dailies.service.spec.ts`): `getAllTasks` — мапит поля, сортирует по `date desc` затем `order asc`, сериализует `date`/`carriedFromDate` через `formatDate` (строки, не `Date`), `carriedFromDate: null` когда пусто. Мокается `PrismaService` напрямую (как в остальных сервис-спеках).
- **Frontend** (`lib/api.spec.ts`): `getAllTasks` дёргает `GET /tasks` (правильный путь/метод).
- UI-компонент `TasksScreen` (фильтры/группировка) тестами не покрывается на этом этапе — в проекте компоненты не юнит-тестятся, тестируется чистая логика в `lib/`. Если группировка выносится в `lib/`, она покрывается спекой.

## Не входит в объём

- **Никакого GTD** — дедлайнов, приоритетов, оценок, inbox, контекстов, проектов, статусов сверх `done`. Это следующий этап (новая модель поверх). Здесь только обзор существующих `DailyTask`.
- **Список read-only** — ни инлайн-тоггла `done`, ни удаления, ни редактирования текста прямо на экране. Все правки — через `DayDetailModal` кликом по дню.
- **Без роутинга** — переключение табов локальным стейтом, URL не меняется, ничего не SSR-ится.
- **YouTube-панель и логика дней не трогаются.** Таб-бар встаёт на уровень sysline, а не на место YouTube.
- **Настройки (шестерёнка) не переносятся** в таб-бар на этом этапе — остаются в `Header` «Главного».
- **Серверные фильтры/пагинация не делаются** — всё отдаётся одним `GET /tasks`, фильтрация клиентская.
