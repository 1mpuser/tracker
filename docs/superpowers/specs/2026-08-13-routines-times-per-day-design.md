# Рутины несколько раз в день — дизайн

Дата: 2026-08-13

## Мотивация

Рутины с недельной нормой (спека `2026-08-12-routines-weekly-goal-design.md`) считают выполнение в **днях**: «позаниматься в качалке 3» означает три разных дня из семи. Отметка — булев факт «в этот день сделал», уникальность `(routineId, date)` физически запрещает вторую отметку за день, поэтому норма и ограничена семёркой.

В эту модель не помещается целый класс рутин, на которые пользователь как раз и забивает: почистить зубы и умыться — дважды в день. Второй чистке некуда записаться: день уже отмечен. Поднять потолок нормы до 14 без изменения модели нельзя — четырнадцать дней в неделе не существует.

## Решения (зафиксировано на брейншторме 2026-08-13)

- У рутины **два числа** вместо одного: `timesPerDay` (сколько раз в день) и `daysPerWeek` (сколько дней в неделю).
- **День закрыт, когда набрал дневную норму.** Неделя меряется в закрытых днях, а не в суммарных отметках. Это правило и не даёт «начистить зубы 14 раз в воскресенье и быть свободным»: воскресенье даст ровно один закрытый день.
- **Обратная совместимость по смыслу:** при `timesPerDay = 1` поведение буквально совпадает с нынешним. Качалка (1 × 3) не меняется.
- **Отметка передаётся абсолютным числом**, а не приращением: «сегодня было 2». Инкрементальный протокол вернул бы накрутку счётчика двойным кликом — этот класс багов в проекте ловили дважды.
- Точка дня перестаёт быть двоичной: при `timesPerDay > 1` заполняется пропорционально сделанному за день.
- Существующие рутины переезжают автоматически: нынешний `weeklyGoal` становится `daysPerWeek`, `timesPerDay = 1`.

## Модель данных

```prisma
model Routine {
  // было: weeklyGoal Int @default(3)
  timesPerDay Int @default(1)
  daysPerWeek Int @default(3)
  // остальные поля без изменений
}

model RoutineLog {
  // добавляется:
  count Int @default(1)
  // уникальность (routineId, date) СОХРАНЯЕТСЯ
}
```

Уникальность `(routineId, date)` намеренно остаётся: одна строка на день, а сколько раз сделано — в `count`. Это сохраняет идемпотентность записи и делает невозможным рассинхрон «сколько строк» и «сколько раз».

**Миграция — три шага, порядок обязателен.** Бэкфилл нельзя писать в тот же файл, что и структурные изменения: правка уже применённого файла миграции ломает контрольную сумму Prisma, на чём этот проект уже спотыкался (см. леджер ветки `feat/routines-weekly-goal`). И бэкфилл обязан выполниться **до** удаления `weeklyGoal`, иначе брать значение будет неоткуда.

1. Добавить `timesPerDay`, `daysPerWeek`, `RoutineLog.count`, сохранив `weeklyGoal`.
2. Отдельной SQL-миграцией: `UPDATE "Routine" SET "daysPerWeek" = "weeklyGoal"` (`timesPerDay` и `count` берут значения из дефолтов).
3. Отдельной миграцией удалить `weeklyGoal`.

**Границы:** `timesPerDay` — 1..10, `daysPerWeek` — 1..7. Верхняя граница дней остаётся семёркой: больше семи дней в неделе не бывает, и теперь это ограничение честное, а не следствие модели.

## Подсчёт — чистые функции

Единственное место, где живёт правило «день закрыт»:

```ts
// backend/src/routines/routines.helpers.ts (новый файл)
export function isDayClosed(count: number, timesPerDay: number): boolean
export function closedDays(logs: { count: number }[], timesPerDay: number): number
```

`RoutinesService.getWeek` возвращает по рутине:

```ts
interface RoutineView {
  id: number;
  title: string;
  timesPerDay: number;
  daysPerWeek: number;
  categoryId: number | null;
  done: number;                                  // закрытых дней на этой неделе
  days: { date: string; count: number }[];       // было: string[]
  order: number;
}
```

`days` меняет форму — теперь это не список отмеченных дат, а список дней с числом отметок. Фронт из него рисует и заполненность точки, и сегодняшний прогресс.

`getHistory` считает `done` теми же `closedDays`, `weeklyGoal` в его выдаче заменяется на `daysPerWeek`.

## Отметка

`POST /routines/:id/log` принимает `{ date, count }`, где `count` — **абсолютное** число отметок за этот день, от 0 до `timesPerDay`. Ноль удаляет строку лога (эквивалент нынешнего `DELETE`). Значение выше `timesPerDay` отклоняется валидацией.

`DELETE /routines/:id/log/:date` сохраняется как есть — им пользуется снятие отметки целиком.

**Связь со сферой** не меняется по сути: галочка `DayCategoryStatus.done` ставится, когда день получает **первую** отметку (`count` переходит из 0 в ≥1). Уменьшение `count` и снятие отметки галочку по-прежнему **не** снимают — асимметрия остаётся намеренной по тем же причинам.

## Фронтенд

**Точка дня.** При `timesPerDay = 1` — как сейчас: пусто или залито. При `timesPerDay > 1` заполняется долей `count / timesPerDay` (линейный градиент по вертикали, цвет — существующий `--accent`, фон — `--panel-alt`; новых токенов не заводим). `title` точки показывает «ср: 1 из 2».

**Клик по точке** циклически увеличивает `count` на единицу, а после дневной нормы сбрасывает в ноль. При `timesPerDay = 1` это в точности сегодняшнее переключение.

**Кнопка сегодняшнего дня** показывает «+ отметить (1 из 2)» и гаснет, когда день закрыт, превращаясь в «✓ сегодня закрыт».

**Счётчик недели** остаётся в закрытых днях: `2/7`.

**Настройка рутины** получает второе числовое поле: «раз в день» (1..10) и «дней в неделю» (1..7). Оба клампятся перед отправкой — как уже сделано для нормы.

**Чистые функции** в `frontend/lib/routines.ts`:

```ts
dayCount(routine: RoutineView, date: string): number
isDayFull(routine: RoutineView, date: string): boolean
nextCount(current: number, timesPerDay: number): number   // цикл 0→1→…→N→0
```

`unclosedRoutines` и `routineRatioColor` продолжают работать без изменений — они оперируют `done` и нормой, а не внутренностями дня.

## Воскресный обзор

Формулировка карточки становится «`«Зубы» — 5 из 7 дней на этой неделе`». Вариант «Снизить» снижает **дни в неделю**, а не разы в день: если человек не вытягивает семь дней, честнее признать пять, чем начать чистить зубы один раз. Снижение `timesPerDay` из обзора не предлагается — это смена смысла рутины, а не признание реальности; делается в настройке.

## Тесты

Бэкенд:
- `isDayClosed` / `closedDays` — граничные значения: `count` меньше нормы, ровно норма, больше нормы (перевыполнение дня закрывает его, но не даёт двух дней).
- `getWeek` считает `done` в закрытых днях, а не в отметках: три дня по одной отметке при норме 2 раза в день дают `done = 0`.
- `POST /log` с `count` выше `timesPerDay` отклоняется; с нулём — удаляет строку.
- Повторный `POST /log` с тем же `count` идемпотентен.
- Галочка сферы ставится при переходе `count` 0 → 1 и не снимается при уменьшении.
- Миграция: существующая рутина с `weeklyGoal = 3` читается как `daysPerWeek = 3, timesPerDay = 1`, её логи — как `count = 1`.

Фронтенд:
- `nextCount` — цикл до нормы и сброс; при норме 1 ведёт себя как переключатель.
- `dayCount` / `isDayFull` — день без отметок, частично закрытый, закрытый.
- Существующие тесты `routines.spec.ts` адаптируются к новой форме `days`.

## Не входит в объём

- Время суток у отметки (утро/вечер) — отметка остаётся привязанной к дню.
- Напоминания по рутинам.
- Разные дневные нормы для разных дней недели.
- История с разбивкой по разам внутри дня — хитмап по-прежнему меряет закрытые дни.
- Изменение существующей асимметрии со снятием галочки сферы.
