# Tracker — обзор системы (актуально на 2026-07-26)

Этот файл — снимок текущего состояния проекта для передачи контекста другой LLM/чату. Он описывает, что система собой представляет **сейчас**, а не историю разработки. Подробные архитектурные детали и соглашения кода — в `CLAUDE.md`, здесь — более человекочитаемый обзор продукта и системы.

## Зачем это существует (не техническая, а личная мотивация)

Это не абстрактный pet-project — это инструмент самоуправления, выросший из конкретной личной задачи, и его стоит оценивать по тому, решает ли он эту задачу, а не по тому, насколько он архитектурно красив.

**Изначальная идея (трекер сфер):** дисциплина и привычка — ежедневная фиксация "сделал / не сделал" по сферам жизни, чтобы не терять регулярность. Из этого же корня растут два конкретных механизма контроля:
- **YouTube-бюджет** — прямой инструмент борьбы с прокрастинацией: ограничить и увидеть, сколько времени утекает в YouTube за день/неделю.
- **Помидорки (Pomodoro)** — не столько техника фокусировки, сколько метрика: "сколько я реально сделал сегодня", объективный счётчик продуктивности, а не ощущение по итогам дня.

**GTD-слой** добавлен позже как отдельный уровень — не вместо трекера сфер, а поверх него. Трекер сфер и помидорки работают на тактическом, дневном горизонте ("что я сделал сегодня"); GTD-слой (inbox → backlog/calendar/someday/waiting/project/reference) нужен для горизонта на несколько дней вперёд — чтобы планирование не сводилось к судорожному разбору задач с утра, а было разложено по системе заранее.

**Текущая реальная проблема (то, из-за чего вообще стоит дорабатывать систему):** несмотря на то, что YouTube-бюджет отслеживается с самого начала, проблема с YouTube **так и не решена** — трекинг есть, но поведенческого эффекта недостаточно. Это открытый челлендж: как довести систему (продуктовым или поведенческим способом — не обязательно кодом) до состояния, где она реально управляет этой привычкой, а не только фиксирует её постфактум. Если другая LLM будет предлагать доработки — это самая ценная точка приложения усилий, важнее любых архитектурных улучшений GTD/iCloud/Obsidian-слоя.

## Что это

Персональный, однопользовательский, self-hosted трекер, живущий на localhost. Без авторизации — весь продукт рассчитан на одного человека (владельца). Изначально был просто трекером ежедневных сфер/привычек, но за последние недели вырос в полноценную GTD-систему (Getting Things Done) с синком во внешние инструменты (iCloud Reminders, Obsidian).

Стек: Docker Compose из 4 сервисов — `postgres`, `backend` (NestJS + Prisma), `frontend` (Next.js App Router), `caddy` (TLS-реверс-прокси для нормальной работы уведомлений и фавиконок в Safari). Пакетный менеджер и рантайм — Bun везде, не npm/node.

Точки входа:
- Frontend: http://localhost:4887 (или https://tracker.performance:4888 через Caddy)
- Backend API: http://localhost:3001
- Postgres: localhost:5434

## Модель данных (Prisma schema)

Две смысловые группы сущностей, которые исторически развивались параллельно:

### 1. Ежедневный трекер (изначальная часть)
- **Category** — сфера жизни (напр. "спорт", "чтение") с `key`/`label`/`order`/`archived` (soft-delete).
- **Day** — один день: `date` (уникальная), `youtubeMinutes`, `pomodoros`, `eveningClosed`, `rating`, `comment`.
- **DayCategoryStatus** — булево "сделано/не сделано" сферы X в день Y.
- **DailyTask** — легаси-модель для задач дня (текст, done, order, carry-over). **UI на неё уже не опирается** — заменена GTD-плитой (`plannedDate`), но модель и `/tasks` эндпоинт в БД остались (backend модуль `dailies` уже выпилен — см. коммит `retire dailies module`).
- **TaskTemplate** — шаблоны повторяющихся задач.
- **Settings** — синглтон-строка настроек (youtube budget, notifications on/off).

### 2. GTD-система (новая, активно растущая часть)
- **GtdItem** — универсальная запись GTD со статусом-конечным-автоматом:
  `inbox → backlog/calendar/someday/waiting/project/reference → done/archived`.
  Поля: `title`, `notes`, `status`, `parentId` (для подзадач проекта, self-relation `ProjectChildren`), `scheduledDate`+`scheduledTime` (для статуса calendar), `plannedDate` (если элемент "взят в сегодня" — это то, что рендерится на главном экране вместо старых DailyTask), `dueDate`, `priority` (bool-флаг важности), `waitingFor`, `order`, `completedAt`.

GTD де-факто заменила механизм ежедневных задач: `Today`-панель на главном экране — это срез GtdItem'ов с `plannedDate == сегодня`, а не отдельная сущность.

## Backend — модули

`backend/src/<feature>/` — NestJS-модули по фичам, каждый со своим `*.controller.ts`/`*.service.ts`/`*.module.ts`/`dto/` и unit-тестом сервиса (мокается `PrismaService` напрямую, без `@nestjs/testing`).

- **categories** — CRUD сфер (`GET/POST /categories`, `PATCH /categories/:key`).
- **days** — `GET/PATCH /days/:date`, `PATCH /days/:date/categories/:key`, `/youtube`, `/pomodoros`, `GET /history`. Каждый эндпоинт принимает произвольную дату, не только "сегодня" — это то, что позволяет `DayDetailModal` работать с прошлыми днями без изменений в бэкенде.
- **stats** — агрегаты для графиков: `GET /stats/categories`, `/stats/youtube`, `/stats/youtube-daily`.
- **task-templates** — CRUD шаблонов повторяющихся задач.
- **settings** — синглтон настроек.
- **gtd** — ядро GTD: `GET /gtd/items?status=`, `POST /gtd/items`, `POST /gtd/items/today` (создать сразу с `plannedDate`), `PATCH/DELETE /gtd/items/:id`. При обновлении статуса на `reference` — синк заметки в Obsidian; при появлении/пропадании "эффективного дедлайна" — синк/удаление напоминания в iCloud (см. ниже).
- **icloud** — `ICloudService`: CalDAV-клиент (через `tsdav`) к iCloud Reminders, env-gated (`ICLOUD_APPLE_ID`, `ICLOUD_APP_PASSWORD`, `ICLOUD_REMINDERS_LIST_NAME`, дефолт списка "GTD"). Если переменные не заданы — сервис молча no-op, приложение работает как раньше. Ключевая идея — **effectiveDue**: у GtdItem "эффективный дедлайн" для напоминания — это `dueDate`, если он есть, иначе `scheduledDate`+`scheduledTime`, но только если статус `calendar`. Генерирует `.ics` (VTODO) и пушит через CalDAV; UID напоминания детерминированный (`gtd-rem-<id>`), поэтому синк идемпотентен. При провальном логине клиент не кэшируется (иначе следующий запрос думал бы, что залогинен, и падал глубже) — это последний фикс в git-истории.
- **obsidian** — `ObsidianService`: экспорт GtdItem'ов со статусом `reference` в заметки Obsidian-хранилища (том монтируется в контейнер через `OBSIDIAN_VAULT_DIR`), тоже env-gated и graceful при отсутствии конфигурации.
- **common** — `date.util.ts`: единый источник правды по датам (UTC-safe хелперы, `parseDateParam` защищается от тихого календарного "перепрыгивания" типа 2026-02-30 → 2026-03-02).
- **prisma** — `@Global()`-модуль, PrismaService доступен везде без явного импорта.

## Frontend — структура

Next.js App Router, но фактически SPA: `app/page.tsx` рендерит один компонент `Dashboard.tsx` (`'use client'`), который владеет почти всем верхнеуровневым состоянием и всё тянет через `useEffect` (никакого серверного рендеринга реальных данных — curl всегда увидит только "загрузка…").

Два таба в `Dashboard`: **Главный** (сферы дня, Today-панель = срез GTD, YouTube/Pomodoro-панели, статистика) и **GTD** (`GtdScreen`).

Ключевые компоненты GTD-раздела:
- **GtdScreen** — табы по статусам-корзинам (Inbox, Backlog, Calendar, Someday, Waiting, Project, Reference, а Done/Archived подгружаются лениво), поиск, счётчики, единственное открытое контекстное меню строки одновременно.
- **InboxProcessor** — воркфлоу разбора корзины (GTD-триаж: куда отправить элемент).
- **GtdItemRow** — строка элемента: инлайн-редактирование, меню "переместить в статус" с выбором даты/времени, бейджи дедлайна/важности.
- **ProjectCard** — раскрывающаяся карточка проекта с дочерними GtdItem.
- **WeeklyReview** — управляемый модал еженедельного ревью, проводит по бакетам (backlog/projects/waiting/someday). Триггерится напоминанием по воскресеньям после 11:00 (локальное время, `isWeeklyReviewWindow`).
- **TodayPanel** — плитка "сегодня" на главном экране, теперь читает GTD (`plannedDate == today`), а не старую DailyTask-модель.

Прочие компоненты главного экрана (`SpheresPanel`, `YoutubePanel`, `PomodoroPanel`, `StatsPanel`, `CategoryHeatmap`, `StreakHeatmap`, `DayDetailModal` и т.д.) — из изначального трекера, устройство подробно описано в `CLAUDE.md`.

`frontend/lib/*.ts` — вся чистая логика, TDD-покрыта: `api.ts` (типизированный fetch-клиент), `date.ts` (`todayLocal()` — единственный источник "какой сегодня день" для всего приложения, специально локальный, не UTC), `streak.ts` (порог засчитывания дня — `completed >= 2` сферы), `heatmap.ts`, `transliterate.ts`, `notifications.ts`, `gtd.ts` (сортировка/бакеты GTD), `pomodoro.ts`.

## Куда идёт продукт (последняя активность)

По git-истории последних ~40 коммитов видно чёткий вектор: **вся разработка последних недель — это GTD-система**, наслаиваемая на изначальный трекер сфер:

1. GTD-ядро (статусы, инбокс, проекты) — базовый CRUD и экран.
2. Мост с главным экраном — "взять в сегодня" (`plannedDate`), при этом старая Tasks-вкладка и DailyTask UI выпилены.
3. Дедлайны и флаг важности (`dueDate`, `priority`).
4. Автоэкспорт reference-заметок в Obsidian.
5. Воскресное напоминание Weekly Review.
6. UX/дизайн-ревью и правки трения (не визуала).
7. Кастомный календарь-пикер в русском стиле (замена нативного `<input type=date>`).
8. **Синк с iCloud Reminders** — самая свежая фича (последние 5 коммитов): CalDAV-клиент, `effectiveDue`-логика, построение `.ics`, синк при изменении и при старте бэкенда, только что пофикшен баг с кэшированием неаутентифицированного клиента.

Design-доки по каждому шагу лежат в `docs/superpowers/specs/` (что решили делать) и `docs/superpowers/plans/` (как реализовывали, по задачам) — если нужна история решений по конкретной фиче, там есть датированные файлы, например `2026-07-25-gtd-icloud-sync-design.md`.

## Известные хвосты / асимметрии, о которых стоит помнить

- Легаси `DailyTask`-модель и её эндпоинт в БД ещё существуют, но UI и backend-модуль `dailies` их больше не используют — GTD (`plannedDate`) их заменила.
- Архивация категории не ретроактивна для истории (см. `CLAUDE.md`, раздел "Archiving semantics") — если день уже трекал архивную категорию, она продолжит учитываться в его статистике, но повторно затоглить её из UI нельзя.
- iCloud- и Obsidian-синки полностью опциональны через переменные окружения — без них приложение работает как раньше, никаких падений.
